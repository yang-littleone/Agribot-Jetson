# 大论文正式试验执行手册

> 现场正常操作请直接使用 `现场简明操作.md` 中的两个入口脚本。本手册保留分步命令，主要用于论文方案、真值测量和故障排查，不要求每次现场逐条执行。

## 1. 试验边界

主体算法和基础参数冻结在标签 `small-paper-complete-20260831`、提交 `fe136784aae94e3fb8c53ce0d73d915cf7742495`。本轮只增加独立的大论文 launch，并增强录包及自动验收脚本；感知、定位、控制算法与基础 YAML 不变。运行时参数只选择是否掉头、首次掉头方向和允许掉头次数。

小论文已有的单行中心线提取与跟踪结果可以作为感知/控制基线。大论文新增验证的重点是：

1. 地头检测：真实地头检出率、非地头误触发率、触发位置误差。
2. 单次掉头：左转和右转的完成率、轨迹误差、耗时、植株接触与安全事件。
3. 下一行重捕获：重捕获成功率、耗时、距离，以及进入下一行后至少 5 m 的跟踪误差。
4. 连续多行作业：4 次交替掉头构成一次任务，统计任务完成率和累计异常。
5. 定位与故障工况：短时定位异常、中心线丢失、低置信度和记录介质异常时，系统是否限速/停车且不失控。

现有程序没有闭环障碍物检测，本试验不能写成“自主避障验证”。人员和障碍物不得进入运动区域，安全依靠隔离区、安全员和急停。

## 2. 正式试验数量

先完成调试试验且不计入论文，再锁定参数进行正式试验。建议最低样本量如下：

| 组别 | 正式次数 | 独立样本单位 |
|---|---:|---|
| 真实地头正样本 | 15 次通过 | 一次完整通过 |
| 非地头负样本 | 15 次通过 | 一次完整通过 |
| 左向单次掉头 | 5 次 | 一次掉头任务 |
| 右向单次掉头 | 5 次 | 一次掉头任务 |
| 连续多行任务 | 5 次，每次 4 个掉头 | 一次完整多行任务 |
| 每种故障工况 | 3 次 | 一次独立注入与恢复 |

同一条轨迹中的视频帧或 20 Hz 日志点不是独立重复，不能当作样本量。

## 3. 人员、场地和真值

至少两人：操作员负责计算机和试验编号，安全员始终握住物理急停并观察机器人。划出机器人运动隔离区；任何人进入隔离区前必须急停、断使能。首次调试掉头时降低速度，并准备人工牵引/支撑方案，但不要在运动中接触机器人。

正式试验前测量并记录：

- 实际相邻行中心距（起点、中点、地头附近至少三处），并取均值作为窗口三的 `headland_row_spacing`。
- 地头可用宽度、机器人最大外廓宽度、设定植株安全间距。
- 每条试验行的真实末端位置。用 RTK、全站仪或固定基准点卷尺测量；同一批试验使用同一方法。
- 下一行中心线真值。沿目标行至少每 0.5 m 设一个测点，或用 RTK/全站仪获取轨迹。
- 同步视频编号，画面应覆盖地头、机器人和行号标识。

复制登记模板，不要直接修改空模板：

```bash
cd /home/wheeltec/agribot/agribot_ws
cp thesis_experiments/templates/trial_register.csv \
  thesis_experiments/trial_register_正式试验.csv
```

布尔字段统一填 `1` 或 `0`；数量字段填整数；未知项先留空，不得事后猜测。失败试验也保留 rosbag、CSV 和视频，并在 `valid` 中注明是否因非系统原因作废。

## 4. 试验编号

一次启动、一个 rosbag、一个自动日志必须共用同一 `TRIAL_ID`。推荐格式：

- 地头正样本：`D_POS_P01_R01`
- 非地头负样本：`D_NEG_P01_R01`
- 左掉头：`F_TL_P01_R01`
- 右掉头：`F_TR_P01_R01`
- 多行任务：`F_MR_P01_R01`
- 故障工况：`X_LOCLOSS_P01_R01`

编号创建后不复用。重复跑同一条件应增加 `R` 编号，而不是覆盖旧数据。

## 6. 每一次正式试验的固定流程

以下以左掉头 `F_TL_P01_R01` 为例。

1. 机器人放到规定起点，姿态和偏移按登记表记录；清空试验区，安全员确认急停。
2. 终端 B 先开始 rosbag：

```bash
cd /home/wheeltec/agribot/agribot_ws
source install/setup.bash
ros2 run centerline_extraction record_field_bag.sh \
  F_TL_P01_R01
```

3. 看到“开始录制”后，终端 C 启动控制器与自动日志：

```bash
cd /home/wheeltec/agribot/agribot_ws
source install/setup.bash
ros2 launch thesis_field_experiments headland_path_tracking.launch.py \
  quality_aware:=true \
  max_distance:=0.0 \
  max_time:=600.0 \
  enable_headland_turn:=true \
  max_headland_turns:=1 \
  headland_min_follow_distance:=1.50 \
  headland_turn_radius:=0.0 \
  headland_exit_distance:=0.25 \
  headland_settle_distance:=0.60 \
  headland_path_step:=0.05 \
  headland_use_continuous_curvature_turn:=false \
  headland_turn_goal_tolerance:=0.10 \
  headland_turn_heading_tolerance:=0.35 \
  headland_reacquire_search_speed:=0.15 \
  trial_id:=F_TL_P01_R01 \
  scenario:=formal_turn \
  repeat_index:=1 \
  headland_turn_direction:=left \
  headland_row_spacing:=0.60 \
  max_linear_speed:=0.18 \
  headland_turn_linear_speed:=0.15 \
  target_distance:=0.20 \
  headland_turn_target_distance:=0.15
```

4. 安全员只在危险时急停。即使触发急停，这次也不能删除，应记入 `emergency_stops` 和事件表。
5. 机器人进入目标下一行后继续运行至少 5 m，再在终端 C 按 `Ctrl+C`，确认控制输出停止。
6. 最后在终端 B 按 `Ctrl+C` 停 rosbag。不要先停 rosbag，否则会丢失结尾状态。
7. 立即填写登记表：是否检测、是否完成掉头、是否进入正确下一行、重捕获、接触、接管、急停和备注。
8. 查看窗口 B 自带的自动验收结果。只有显示通过才算数据链完整；验收失败不代表系统性能失败，而是数据不完整，需要按新的试验编号重做。

## 7. 各组命令与观察项目

### 7.1 地头检测

真实地头正样本和非地头负样本都使用三窗口命令。窗口三以简明操作中的完整命令为模板，分别设置 `scenario:=headland_positive` 或 `scenario:=headland_negative`，并设置 `enable_headland_turn:=false`。

`detection` 模式关闭自动掉头，只用于记录检测输出。正样本记录首次 `/headland_detected=true` 相对真实行末的位置误差；负样本在完整正常行段中统计错误触发次数。检测到地头或中心线消失后，应由操作员安全停止本次通过。

### 7.2 单次掉头和重捕获

窗口三以简明操作中的完整命令为模板。左转设置 `headland_turn_direction:=left`，右转设置 `headland_turn_direction:=right`，两组都设置 `max_headland_turns:=1`。

左、右组分别进行，起点、速度、作物条件尽量配对。记录 `ROW_FOLLOW → U_TURN → NEXT_ROW_REACQUIRE → ROW_FOLLOW` 是否完整出现。人工确认“正确下一行”，并测量掉头轨迹误差、最终横向/航向误差和进入下一行后 5 m 区段的 P95 横向误差。

### 7.3 连续多行任务

窗口三以简明操作中的完整命令为模板，设置 `max_headland_turns:=4`。可用 `headland_turn_direction:=left` 或 `right` 指定第一次掉头方向，之后程序自动交替。

程序会自动左右交替，最多 4 次掉头。一次任务只有在 4 个掉头和 4 次下一行重捕获全部完成，且最终继续跟踪至少 5 m 后才算完成。中途失败不能把成功的几个掉头拆成独立正式样本，但可单独报告“逐掉头成功率”。

### 7.4 故障与安全测试

先在车轮架空、周围无人条件下验证系统反应，再以最低风险方式进入田间。不要拔电源、遮挡人员或在运动区放置障碍物。每种条件独立做 3 次并记录事件时间：

- 感知低置信度/中心线丢失：在固定位置使用可移除的非人员遮挡物影响传感器视野，观察是否限速或停车；不得遮挡激光雷达近场安全区域后让车盲行。
- 定位数据短时异常：优先离线回放 rosbag 检查；若必须实车注入，只能使用已有的安全开关/节点停发方式，并由安全员急停保护，记录开始、结束和恢复时间。
- 记录介质异常：不让车运动，在架空或急停状态下测试不可写输出目录，确认自动日志退回工作空间；正式田间运行不主动拔 U 盘。
- 节点异常：只在架空状态停止感知节点，确认控制输出趋零/安全状态变化，然后重新启动整个试验栈，不做带故障继续行驶试验。

故障测试评价的是安全降级和可恢复性，不是避障能力。

## 8. 成功判据

正式单次掉头成功必须同时满足：

- 自动日志出现完整状态序列；
- 掉头完成并进入计划的相邻行；
- 下一行稳定重捕获，继续跟踪距离不少于 5 m；
- 无茎秆碰撞、无人工接管、无急停；
- rosbag 和自动 CSV 通过完整性检查。

多行任务还必须完成 4 个交替掉头。叶片轻触不直接等同茎秆碰撞，但必须单独计数并报告。软件中的 0.20 m 位置容差、0.35 rad 航向容差和 0.70 重捕获置信度是程序判定阈值，不可当作实测精度结论。

## 9. 离线汇总

完成并核对现场登记表后执行：

```bash
cd /home/wheeltec/agribot/agribot_ws
python3 thesis_experiments/scripts/analyze_trials.py \
  --results-root thesis_experiments/results \
  --register thesis_experiments/trial_register_正式试验.csv \
  --output-dir thesis_experiments/analysis/formal
```

输出：

- `trial_summary.csv`：每一次试验的状态序列、掉头/重捕获时间距离、控制量和人工真值。
- `group_summary.csv`：按模式与场景统计样本量、成功率及均值/标准差。

自动统计不能代替人工真值。论文表格应同时报告样本量、成功次数/成功率、均值、标准差；条件允许时再报告中位数和 P95。所有排除数据都要给出预先定义的排除原因，不能只删除失败结果。

## 10. 每日收尾

按顺序停止终端 C、终端 B、终端 A，确认底盘不再接收速度命令。随后备份 `bags/`、`results/`、现场登记表、事件表和视频索引到第二块存储介质。最后再次执行：

```bash
thesis_experiments/scripts/verify_frozen_code.sh
```

保存当天的冻结检查输出、天气、土壤、植株生长期、行距范围和异常说明，作为论文可复现实验条件。
